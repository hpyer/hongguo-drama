## 复核后的补充修复

- 设置保存由主进程排队，执行时读取最新设置，避免较早的代理保存覆盖稍后关闭的自动删除；保存和失败恢复均有等待上限。过期原生代理操作完成后恢复当前选择，不再写回旧环境代理；更新下载也使用当前目标代理。启动代理未确认时暂停发现列表和自动更新检查，界面保留具体错误原因。
- 便携标记识别与资料迁移分离，显式 `--user-data-dir` 仍保持便携更新限制。
- 在线工作记录保留到清理完成；取消后移出复用缓存的任务、协议回退的 HLS/解密任务及尚未关闭的磁盘读取句柄，退出时也会等待。
- HLS 暂存与输出位于同一磁盘，同设备任务共享未落盘数据与最终 MP4 的预留额度，另留 512 MiB；写入中、转封装前和转封装中复查。容量故障使用小额度夹具验证，没有实际填满磁盘。
- 官网全集解析只从当前播放路由的 `seriesDetail` 读取身份和分集，拒绝缺身份、错配与异常列表。分享链接的编码数字不再被文本正则截短；重定向已包含有效 ID 时不请求目标页面。URL 外已有明确 ID 的文本保持本地解析、不访问其中的私网或凭据链接。
- 发布前真实页面核对补齐官网整剧页和具体分集页的两种明确路由，均从同一详情对象检查剧集身份；不再因整剧路由键不同而拒绝正常内容。
- 官网“加载更多”补齐成功返回格式；西饭、河马和自定义源也返回统一分页状态。所有通道最多 50 页，到上限结束，超界或非整数页明确报错。App 游标缺失偏移时按页码回退，`null` 不再变为零。
- 分页请求同步去重；旧响应、旧计时器不能解除新请求的锁。换词、换来源、离页和重搜清理所属请求；分页超时仍显示已完成来源，失败来源保留游标供重试。

## 3.4 修复批次（R01–R14）

- R01 代理：保存设置前先校验协议/主机/端口，并在落盘前让新代理生效；应用或保存失败恢复旧代理。启动时坏配置改为有界超时后临时直连，自动续下载与追剧刷新暂停，主窗口仍打开并提示到设置修复，不再在创建窗口前退出。
- R02 删除全部：统计和删除共用同一目标集合，已移除档案和只有下载任务的剧也计入；确认框说明包含已移除但保留的视频。
- R03 设置页：重新进入时刷新播放器里改过的自动删除、缓存、兼容模式等共享选项，同时保留用户未保存的草稿。
- R04 观看记录：后台刷新在网络等待后重新读取当前档案，较新的分集列表、移除状态和播放进度不会被较旧的响应覆盖。
- R05 便携更新：应用内更新判断复用 `portable.marker` / 回退模式识别；目录式 ZIP 和程序目录不可写时也只提供手动更新。
- R06 搜索预算：西饭、河马搜索继承同一次搜索的剩余截止时间，超时请求不再各花 10 秒叠加。
- R07 重试/继续：保存队列失败时恢复任务字段和队列，单个重试、批量重试、继续全部都不会留下未持久化却会自动启动的任务。
- R08 热播推荐：有播放记录时显式续播保存的可播分集，无记录或记录已锁定/失效时从首个可播分集开始。
- R09 退出：在线 HLS/解密准备任务纳入退出等待，先中止再等待清理；清理超时仍取消退出。
- R10 HLS 清单：先收集完整 Buffer 再统一 UTF-8 解码，中文文件名跨数据块不再被损坏。
- R11 HLS 暂存：在输出文件所在盘建立暂存目录，共享分片与输出空间预算，失败清理临时目录。
- R12 剧集身份：官网页和备用接口都核对请求的剧集编号，拒绝另一部剧的分集或第一个对象的兜底。
- R13 来源页面：空结果时“打开来源页面”携带当前关键词对应的红果搜索网址。
- R14 分享链接：文本中的 `series_id` 只接受完整键名和 1–30 位数字边界，`not_series_id`、31 位截断等不再误匹配；已有 ID 时不发网络请求。

## 搜索（Issue #47、#48）

- 红果来源改为直接请求官网搜索接口 `https://hongguoduanju.com/api/search/result`：单次 10 秒超时、最多重试一次、成功结果缓存 60 秒。搜索页本身是前端空壳，结果由页面脚本请求同一接口生成；旧实现让隐藏窗口轮询 DOM，页面偶发显示「加载失败，请刷新页面重试」时会空等到 15 秒，这是「红果搜索超时」和「查找下一季超时」的共同原因。
- 隐藏窗口嗅探保留为接口地址或结构变化时的兜底；页面显示「加载失败」时自动刷新一次。接口超时或 5xx 不做页面兜底，直接显示可重试错误，避免再等一次 15 秒。
- 搜索标题比较忽略空白、全角/半角和标点，例如「言出法随，诸天万界我说了算」与「言出法随 诸天万界 我说了算」视为标题匹配；来源自身的模糊结果仍按部分匹配排在后面。完整剧名没有匹配时，先用去掉标点和空格的同一关键词、再用首段各补搜一次（最多两次）；命中完整标题即停止，界面会标明补搜关键词，补搜失败保留第一次结果。
- 接口返回非空列表但无法识别任何条目、或页面兜底明确显示「加载失败」时，按失败提示处理，不再显示成「没有找到」。空响应、HTML 内容或带错误码的响应按服务错误重试，不写入缓存。
- 官网搜索有一部分条目 `video_data` 为空、剧集编号放在 `item.keyword`；解析器已兼容该结构，不再把这类正常结果误判成「解析失败」而丢弃。
- 分享链接若已含 `/player/<id>`、`detail?series_id=`、`video_series_id`，或分享文本里带显式 `series_id=`，直接本地取编号，不再先发网络请求；网络失败时错误会附带具体原因。
- 搜索方案调研参考了 hongguoTV 的「接口优先、网页兜底」思路；App 搜索签名适配自现有 drpys/hongguoTV GPL 代码路径，但默认仍使用官网公开接口，App 搜索需在设置中显式开启。
- 搜索共用 20 秒总预算：主进程补搜在预算到期后返回已有结果并标注部分完成；搜索面板另有 25 秒兜底，超时后保留已完成来源的结果、列出未返回的来源，而不是把成功结果一起丢掉。页面兜底沿用同一个截止时间：排队、加载和轮询都计入预算，到期返回部分完成，不再从 15 秒重新计时。
- 模糊补搜失败不再被吞掉：原词和补搜都没有结果时返回失败；已有原词结果时标记部分完成并说明补搜错误。
- 查找下一季新增前端 25 秒兜底：超时后显示「查询超时，请稍后重试」并保留重试入口，不再一直转圈；每次查询只清理自己的计时器，旧请求晚到不会解除新查询的超时保护。主进程查询成功后仍按本地候选优先合并。
- 官网接口每页 10 条，现已支持「加载更多」；搜索首屏选中的通道会固定用于后续分页，第二页失败不会暗中切换来源。App 搜索每页 20 条并使用 `search_id/passback/next_offset` 游标。
- 2026-10-25 实测：接口正常时约 0.2–1.8 秒返回结果（10 条/页，并带总数与总页数），包含封面、集数与简介；接口会偶发 502 或挂起，重试可恢复。用《谁说纨绔不能当状元》完整剧名和部分剧名「纨绔不能当状元」均能返回正剧及各季，后者此前会因 `video_data` 为空被当成解析失败。接口未公开，字段和可用性可能变化，页面嗅探兜底与明确错误提示因此保留。

## App 搜索与加载更多（R15/R16，实验）

- 设置页新增「实验：红果 App 搜索」开关，默认关闭。开启后红果来源先请求 App 搜索（3.5 秒子预算），有标题匹配才采用；失败、空响应、无标题匹配或无短剧 tab 时自动回退官网 API，再按现有规则使用页面兜底。
- App 搜索复用现有 drpys/hongguoTV GPL 签名算法和纯 JS SM3，单独生成 GET 查询签名，不改变播放取址参数；只接受 hash branch 0，临时设备标识不落盘。
- App 搜索解析 `search_tabs` 的短剧 tab（11），只接受带 `video_data` 的 cell，避免把「相关搜索」等 header 当成剧；HEIC 封面留空占位，由官网回退/占位图兜底。
- 搜索会话保存首屏通道和游标；「加载更多」只按该通道取下一页，全部来源分别保存、合并去重，页面兜底不提供翻页。App 连续失败/空响应有 2 分钟冷却，避免每次搜索都多等。
- 2026-10-25 实测：App 搜索对《谁说纨绔不能当状元》返回目标剧及部分季，第二页出现宽泛结果或 200 空响应；因此保持实验开关，不把 App 搜索宣称为与手机 App 完全一致。官网 API 仍为默认通道。

## Windows 便携版资料（Issue #47）

- 单实例锁在读取/迁移便携资料之前取得，同一便携目录的并发启动不会再互相清理 `.importing` 临时文件。迁移先完整暂存、全部复制成功后才提交；提交失败回滚本次新建文件，删不掉的残留用 `data/.migration-incomplete` 标记，下次启动识别并回退系统目录，不会把半套资料当成完整资料。
- 单文件便携 EXE（包括从便携 ZIP 解压出的同一个 EXE）读取 electron-builder 的 `PORTABLE_EXECUTABLE_DIR`；用 `npm run build:zip` 生成的解压即用目录则通过打包时写入的 `portable.marker` 识别。两种便携版都把 `data.json`、`danmaku-client.json` 放到程序目录的 `data` 子目录；首次启动只复制系统配置目录里缺失的文件，不删除原文件、不覆盖已有文件，临时缓存不迁移。搜索历史、在线清晰度等浏览器本地存储在切换后的新资料目录重新建立，不迁移旧目录里的这部分数据。
- 程序目录不可写时继续使用系统配置目录，并在设置页说明原因；旧资料复制失败会回滚本次已复制的文件并回退旧目录，不会带着空资料进入便携目录。移动或备份程序时连同 `data` 文件夹一起保留即可。
- 设置页新增「配置文件位置」，显示当前实际目录，并区分便携版与安装版说明。启动参数显式指定用户资料目录时不覆盖该选择。`npm run build:zip` 会拒绝打包含 `data` 运行资料的 win-unpacked，并在 `portable.marker` 无法移除时以非零退出，避免污染后续安装版构建。
