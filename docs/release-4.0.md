## 普通与紧急远程公告

- 分别读取普通、紧急远程公告。设置页提供「关闭普通公告」「关闭紧急公告」两个独立开关，默认接收，选择跨重启和软件升级保留。自动提醒关闭时不读取、不展示对应通道。
- 普通公告正文已包含：可在「设置 → 公告通知」永久关闭普通或紧急公告，升级后保持关闭，并可点击「查看当前公告」手动查看。永久关闭与 `day`／`version` 临时免提醒分开，本次已读回核对。
- 每条弹窗显示 30 秒自动收起，也可手动关闭。关闭当前弹窗不写入普通免提醒偏好。
- 紧急公告优先；启动检查，运行期间每 5 分钟检查一次，同一紧急 ID 自动提醒永久一次，跨天、重启和升级不重复。已读记录需成功保存并保留在本机，删除资料或更换设备会失去去重记录；保存失败必须提示。
- 新紧急公告须使用新 ID；仅修改正文或重新启用旧 ID 不会再次自动提醒。紧急公告绕过普通免提醒，但遵守紧急独立关闭开关。
- 普通公告支持「今日打开不再提醒」（`day`）与「版本更新前不再提醒」（`version`）。自动检查在免提醒生效时不读取普通远程文件；`day` 按本机日期隔天解除，两个免提醒均在软件版本变化后解除，两个独立关闭开关仍保留。
- 自动检查每进程最多读取普通文件一次，失败不连续重试；手动查看是用户主动重新读取的独立入口。

## 手动查看与三处交互

- 设置页「查看当前公告」重新读取当前远程公告，紧急优先。即使自动提醒关闭、普通 `day`／`version` 免提醒生效、紧急 ID 已读，也可手动查看，不修改两个开关及免提醒偏好；紧急展示仍保存已读记录。无有效公告或读取失败时显示提示。
- GitHub 反馈：点击在系统浏览器打开项目反馈网页。
- 邮箱反馈：点击复制邮箱地址，并反馈复制结果。已实现点击即复制及成功/失败反馈；不会打开邮件应用。
- AI 服务购买说明：含 `vipai.pro` 的标题与购买说明整段作为链接，点击在系统浏览器打开固定购买网站。链接交互验收不代表网站购买流程已经验证。

## 四项审核修复范围

1. 普通公告请求绑定发起时的开关状态；关闭再开启后丢弃旧请求的迟到结果，有效缓存仍可复用，保持自动检查每进程最多读取一次。
2. 公告随当前全屏容器和焦点移动，退出全屏回到普通界面；移动不重复确认紧急已读，不重置 30 秒展示计时。
3. 修改普通公告开关不重置紧急公告的 5 分钟检查时钟。
4. 公告 JSON 使用真实服务解析器验证格式，不把维护性正文固定措辞写成回归前提。

以上均已纳入 4.0 正式版，定向记录见 [公告维护说明](announcements.md)。

## 搜索 #60：官网错误时自动使用注册身份的 App 搜索

- 实测复现官网搜索 HTTP 502（用户报告为 HTTP 503）以及旧 App 搜索空响应。平台注册的匿名身份加原搜索签名可返回结果，同身份无签名仍返空；搜索保留签名，不能直接照搬播放接口的无签名请求。
- App 搜索与播放共用进程内匿名注册身份，翻页保持同一身份和原始游标；不登录账号、不导入用户 Cookie、不把匿名身份写入文件。无效输入及注册失败不会发送随机身份搜索。
- 默认仍优先官网；官网失败时自动尝试 App 搜索，成功保留可读提示及 App 分页通道，再失败才尝试既有上新目录补搜。不能把全部上游不可用报告成“没有结果”。
- App 正常返回空结果时不再让其他关键词进入两分钟故障冷却。设置中的 App 搜索开关表示“优先使用”；关闭时保留官网故障后的备用能力。
- 定向证据：11项 App 搜索单元检查通过；503/502故障回退及分页回归通过。真实 App 接口搜索“接班”“归路”均返回结果；模拟官网503、使用真实 App 接口的主进程搜索返回11条聚合结果，第二页返回17条。官网后来一次正常请求也恢复返回22条，说明其可用性存在波动。
- 未取得 #60 作者的具体关键词与网络环境，不能据这些样本保证所有地区、作品或未来接口可用。
