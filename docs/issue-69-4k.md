# Issue 69：4K 布局适配

2026-10-29，本地适配已完成，纳入4.6发行目标；实际打包与发布状态见 `release-4.6.md`。

## 行为

- 发现页和搜索页内容使用可用宽度，移除 1180px 上限。
- 发现页海报随窗口宽度自动排列；提供小、标准、大、特大四档，保留 3:4 比例。骨架屏与海报共用排列规则，窄窗口允许收为一列。
- 设置的外观区域增加“界面与字号”。复用已有窗口缩放与 `ui_zoom` 保存逻辑，支持 50%–200% 和恢复 100%；快捷键改动会同步百分比。
- **未设置时默认 100%。窗口变大、全屏或连接 4K 屏不会自动调整缩放。已有的用户手动选择继续保留。**
- 主进程 `getDefaultSettings()` 明确写入 `ui_zoom: 1`。新建隔离资料冷启动后，`get-settings.ui_zoom` 和实际窗口 `getZoomFactor()` 均确认是 `1`，并已打开供用户测试。
- 海报大小与界面缩放独立保存。字号随界面整体缩放，不提供单独改变文字而保持按钮尺寸的选项。
- 页头空间不足时换行；侧栏内容过高时滚动，底部账号与设置仍可访问。

## 验证

1. `node scripts/check-window-layout.cjs` 通过：默认缩放、窗口尺寸独立性、保存与恢复、边界、错误处理、响应式字体规则；新增海报偏好四档、非法值、启动恢复、保存失败保持原状态的断言。新增断言在实现前确认失败，实现后通过。
2. Ego Lite 界面流程使用隔离 Electron 主进程、临时资料及真实红果 App 目录。临时本机桥接调用实际设置和目录 IPC，未伪造片单。原生窗口和浏览器媒体均未执行播放；Electron 已核对静音。
   - 3840×2160、100%：片单宽约 3554px，标准海报每行 11 张，无横向溢出。
   - 手动 150% 的 4K 等效 CSS 视口 2560×1440：大海报每行 6 张；实际 Electron `getZoomFactor()` 与保存值均为 1.5，重载后设置仍正确。
   - 1100×750：标准海报每行 4 张，特大每行 3 张；修正页头后无标题挤压。
   - 550×375：特大海报一列，片单和页头无横向溢出，侧栏内容与底部入口均可访问。
   - 浅色与深色设置界面已查看；外观机械检测无发现。
   - 用户要求默认 100% 后，已移除“4K 可先试 150%”的文案，并通过实际 IPC 将本轮测试窗口恢复到 1.0。150% 仅为测试中手动选择的值，不是默认策略。

## 限制

4K 布局使用 Chromium 视口模拟，未覆盖实体 4K 显示器及 Windows 实机。开发服务模块转换卡住后，改用临时 esbuild 静态预览；未宣称 Vite 正式构建通过。未验收视频播放、下载、画中画、连播或自动删除。本轮测试不影响正式应用的视频、账号和记录。
